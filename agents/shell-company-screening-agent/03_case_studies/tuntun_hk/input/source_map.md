# 港股资产重组标的筛选数据源说明

## 一、文件用途

本文件用于说明港股资产重组标的筛选 Agent 应使用哪些数据源、每个数据源负责哪些信息、数据优先级如何排序，以及不同层级结论如何使用不同等级的数据来源。

- `02_prompts/shell_screening_prompt.md` 负责定义业务逻辑和报告结构；
- 本文件负责定义数据来源、取数规则与来源分层；
- 最终目标不是只支撑“事实层”，而是同时为“约束层、商业层、情景层”提供边界清晰的数据支持。

---

## 二、数据源优先级

### Priority 1：官方来源

官方来源用于关键事实核验。凡涉及年报、中报、公告、股权结构、停牌复牌、审计意见、监管风险、重大交易和反收购风险的判断，应优先回到官方来源验证。

### Priority 2：结构化数据源

结构化数据源用于批量初筛，例如股票代码、市值、P/B、成交额、行业分类、基础财务指标等。结构化数据可以提高效率，但不能替代官方文件核验。

### Priority 3：辅助商业与行业来源

行业资料、公司官网 IR、主流财经媒体、对标案例和品牌/渠道公开资料，可用于支持商业 thesis、行业类比和战略 optionality，但不得替代官方事实来源。

### Priority 4：工程参考来源

GitHub 爬虫项目、社区代码和第三方脚本只作为工程参考，用来学习抓取路径、页面结构、PDF 下载方式和批量处理思路，不作为权威数据来源。

---

## 三、四类结论与数据源使用规则

### 1. Fact（事实层）
适用数据源：
- HKEXnews / 披露易
- 年报 / 中报 / 业绩公告
- 官方权益披露
- 审计报告
- HKEX 官方上市公司名单

要求：
- 尽量可回溯到具体文件、日期、页码或公告标题；
- 在证据表中优先标为 `support_level = audited` 或 `official`。

### 2. Inference（推断层）
适用数据源：
- Fact 层的多个已验证信息
- 公司官网 IR
- 主流财经数据库
- 行业公开资料

要求：
- 必须说明推断依据；
- 不得伪装成已验证事实。

### 3. Assumption（假设层）
适用场景：
- 估值敏感性测试
- 交易结构比较
- 时间表假设
- 客户预算假设

要求：
- 必须明确写出前提条件；
- 不得把假设结果写成公司现状事实。

### 4. Hypothesis（战略假说层）
适用数据源：
- 已验证事实 + 行业类比
- 公司官网 / IR / 品牌公开资料
- 对标案例
- 主流财经媒体或可信行业观察

适用场景：
- 渠道扩张 optionality
- 品牌 / IP 联动 optionality
- 国际化 optionality
- 平台升级 thesis
- 资本市场再定价逻辑

要求：
- 必须在证据表中标出 `claim_type = hypothesis`；
- 必须说明依赖前提；
- 不得使用无来源的伪精确协同比例、伪精确周期或无依据 DCF 结论。

## 四、核心数据源

## Source 1：HKEXnews / 披露易

- **Source ID:** `HKEXNEWS_OFFICIAL`
- **类型:** 港交所官方公告与公司文件来源
- **优先级:** Priority 1
- **主要用途:**
  - 年报
  - 中报
  - 业绩公告
  - 公司公告
  - 通函
  - 股东大会文件
  - 停牌 / 复牌公告
  - 更换董事、核数师辞任
  - 配售、可转债、认股权证、收购、出售、重组公告
  - 监管问询、纪律处分、重大风险公告

- **适用字段:**
  - 公司名称
  - 股票代码
  - 主营业务
  - 财务数据
  - 审计意见
  - 股权结构
  - 控制权变化
  - 停牌复牌状态
  - 重大交易历史
  - 诉讼、仲裁、监管风险
  - 品牌许可、控制权敏感条款、重大合同线索

- **验证规则:**
  - 进入 Top 3–5 shortlist 的公司，其财务数据、股权结构、审计意见、重大风险和交易历史必须尽量回到 HKEXnews 文件验证。
  - 若其他来源与 HKEXnews 不一致，以 HKEXnews 官方文件为准。

---

## Source 2：AKShare 港股数据

- **Source ID:** `AKSHARE_HK`
- **类型:** 第三方结构化金融数据工具
- **优先级:** Priority 2
- **主要用途:**
  - 获取港股基础行情
  - 获取股票代码、股票简称、价格、成交额
  - 获取市值、P/B、基础估值指标
  - 用于第一轮批量初筛

- **适用字段:**
  - 股票代码
  - 股票简称
  - 当前价格
  - 市值
  - P/B
  - 成交量
  - 成交额
  - 行业分类
  - 基础财务指标

- **验证规则:**
  - AKShare 可用于初筛，但不能作为最终报告关键事实的唯一来源。
  - 进入 shortlist 的公司，其关键财务数据和重大判断必须尽量回到 HKEXnews 年报、中报或公告验证。

---

## Source 3：HKEX 上市公司名单

- **Source ID:** `HKEX_LISTED_COMPANY_LIST`
- **类型:** 官方上市公司基础名单
- **优先级:** Priority 1
- **主要用途:**
  - 构建港股全市场 universe
  - 获取股票代码、公司名称、板块、上市状态
  - 区分主板和 GEM

---

## Source 4：公司官网 / IR 资料

- **Source ID:** `COMPANY_IR`
- **类型:** 公司官网、投资者关系资料、品牌官网
- **优先级:** Priority 3
- **主要用途:**
  - 辅助理解业务模式、品牌结构、零售网络、渠道描述
  - 支撑一部分商业 thesis 与场景协同分析

- **限制:**
  - 不能替代官方审计与公告信息；
  - 品牌宣传语不得直接当作财务或交易事实。

---

## Source 5：行业资料 / 主流财经媒体 / 对标案例

- **Source ID:** `INDUSTRY_AND_COMPARABLES`
- **类型:** 行业公开资料、主流财经媒体、研究文章、公开对标案例
- **优先级:** Priority 3
- **主要用途:**
  - 形成行业类比
  - 支撑平台升级 thesis
  - 支撑渠道扩张、国际化、品牌联动的 hypothesis
  - 提供资本市场再定位的启发性参考

- **限制:**
  - 默认只能用于 `inference` 或 `hypothesis`；
  - 不得直接替代审计、公告或官方事实；
  - 对标案例只能作为启发，不得写成“本项目必然复制”。

---

## Source 6：GitHub HKEX 爬虫项目

- **Source ID:** `HKEX_CRAWLER_REFERENCES`
- **类型:** 工程参考
- **优先级:** Priority 4
- **主要用途:**
  - 参考 HKEXnews 页面结构
  - 参考公告搜索和 PDF 下载逻辑
  - 辅助开发本项目自己的抓取脚本

- **规则:**
  - 可以参考代码逻辑；
  - 不直接依赖其输出结果；
  - 所有结果必须回到 HKEXnews 官方页面验证。

## 六、采集流程

### Step 1：构建全市场 universe
从 HKEX 上市公司名单获取全部港股上市公司，保存为：

`data/raw/hkex_full_universe.csv`

### Step 2：拉取结构化市场数据
使用 AKShare 拉取港股行情、市值、P/B、成交额等字段，保存为：

`data/raw/akshare_hk_market_snapshot.csv`

### Step 3：第一轮估值过滤
根据市值、P/B、成交额、板块、上市状态等字段生成初筛候选池。

### Step 4：抓取官方公告和报告
对初筛候选公司，从 HKEXnews 抓取最近 3–5 年年报、中报、重大公告、停牌复牌公告、配售/可转债公告和重组公告。

### Step 5：解析文本和提取风险信号
解析 PDF / HTML，提取主营业务、财务数据、审计意见、股权结构、债务、诉讼、监管风险和交易历史。

### Step 6：建立证据表
对进入 shortlist 的公司，建立 `source_evidence_table.csv`，记录每个关键事实、关键判断和关键假说的来源、日期、文件位置和结论类型。

## 七、数据质量与叙事边界规则

1. 不得编造缺失数据；
2. 对无法确认的数据，写“未能从公开资料确认”；
3. 市值、P/B、股价、成交额必须标注日期；
4. 财务数据必须标注报告期和来源文件；
5. AKShare 只用于初筛，不作为最终关键事实的唯一来源；
6. GitHub 爬虫只作为工程参考，不作为权威数据；
7. PDF 解析结果必须保留原文件路径，便于人工复核；
8. 进入 Top 3–5 shortlist 的公司，必须建立证据表；
9. 若多个来源不一致，以官方文件优先；
10. 若官方文件无法确认，应在报告中明确说明，不得模糊处理；
11. 若结论用于战略层或情景层，必须在证据表中标出 `claim_type` 与 `assumption_dependency`；
12. 不得使用无来源伪精确数字来增强商业说服力。

---

## 八、Source Evidence Table 使用结论

本项目采用分层数据源结构：

1. **官方来源：** 负责事实层与约束层；
2. **结构化来源：** 负责初筛效率；
3. **辅助商业来源：** 负责支撑行业类比与平台升级思路；
4. **工程参考来源：** 负责辅助开发，不进入正式结论。

最终单报告中的关键判断必须能回溯到具体来源文件、日期和证据位置；
商业层的吸引力表达也必须保留来源类型、结论类型和前提条件，做到“可讲，但不越界”。
